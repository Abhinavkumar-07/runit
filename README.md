[![node version](https://img.shields.io/badge/node-%3E%3D18-blue.svg)](https://nodejs.org)

**One command to detect, install, and run any codebase.**

Whether you just cloned an unfamiliar repository, received a folder from a teammate, or got code generated by an AI: getting it running is usually a chore. Python needs a virtual environment and `pip`; React needs `npm`, `pnpm`, or `bun`; backend and frontend folders must be started in separate terminals.

`runit` inspects the project tree, sets up only what is missing without rewriting lockfiles, starts the app (and any companion services), and gives you a clickable localhost URL.

```bash
cd some-project
runit
```

```text
[runit] Scanning project...
✔ frontend (Next.js) is ready -> http://localhost:3000   (Ctrl+click to open)
✔ backend  (FastAPI) is ready -> http://127.0.0.1:8000
   API docs -> http://127.0.0.1:8000/docs
```

## Highlights

- ⚡ **Zero Setup & Zero Dependencies**: Runs directly via `npx runit-dev` or a global install. Lightweight and fast.
- 🔍 **Universal Stack Detection**: Introspects code and manifests for Node.js, Python, Go, Rust, Java, PHP, Ruby, Docker Compose, and static HTML.
- 📦 **Smart Delta Installs**: Reuses existing virtual environments and system packages (e.g. system `numpy`/`pandas`). Never re-downloads packages you already have.
- 🔒 **Safe by Default**: Uses `--no-save` to protect your lockfiles from unwanted mutations. Strips sensitive cloud/CI credentials from install environments. Warns on untrusted registries and custom install scripts.
- 🤹 **Multi-Service Coordination**: Automatically discovers and launches companion folders (`frontend/` + `backend/`, `client/` + `server/`, `apps/*`) concurrently with color-coded logs.
- 🛑 **Bulletproof Process Management**: Guaranteed process cleanup on `Ctrl+C` across Linux, macOS, and Windows—even for detached daemon processes. Includes background session tracking (`runit status` & `runit stop`).
- 💡 **Helpful Diagnostics**: Detects occupied ports, missing system compilers (`gcc`, Visual C++ Build Tools), pending database migrations, missing `.env` parameters, and suggests immediate copy-paste solutions.

Run instantly without installing:
```bash
npx runit-dev
```

```bash

```

> **Requirement**: Node.js 18 or newer. No additional tools or external package dependencies required.

## Usage

```bash
runit [folder] [options]
```

### Commands

| Command | Description |
|---|---|
| `runit` | Scan the current folder, install missing dependencies, and launch services. |
| `runit path/to/project` | Run a specific project directory. |
| `runit status` | List active `runit` sessions and their child processes. |
| `runit stop [folder]` | Terminate a running session and all child processes started by it. |

### CLI Options

| Flag | Description |
|---|---|
| `--dry`, `--dry-run` | Inspect and print the detected execution plan without installing or running anything. |
| `--no-open` | Prevent `runit` from automatically launching the application in your default browser. |
| `--yes`, `-y` | Skip first-run confirmation prompts and permit project-specified package repositories. |
| `--safe` | Skip third-party dependency install hooks (`--ignore-scripts` for Node, pre-built binary wheels only for Python). |
| `--clean-env` | Restrict environment variables passed to the application to an essential whitelist. |
| `--env=FOO,BAR` | Whitelist specific environment variables when `--clean-env` is active. |
| `--all` | Allow launching more than 5 services concurrently. |
| `--version`, `-v` | Display the installed version. |
| `--help`, `-h` | Display usage instructions and available options. |

## Supported Ecosystems

`runit` detects project types by inspecting configuration files, lockfiles, and application code:

| Stack | Detection Method | Execution Command |
|---|---|---|
| **Next.js, Nuxt, Astro, Vite, SvelteKit, Remix, Angular, CRA** | `package.json` dependencies & scripts | `dev`, `develop`, `start`, or `serve` script via detected package manager |
| **Express, Fastify, NestJS, Koa, Node.js** | `package.json` scripts or server entry point (`server.js`, `index.js`, `app.js`) | Package script or `node <entry>` |
| **FastAPI** | `FastAPI(` in Python files, or `fastapi` in requirements | `uvicorn <module>:app` |
| **Django** | `manage.py` | `python manage.py runserver` |
| **Flask** | `Flask(` / `create_app()` in code or `flask` dependency | `flask run` or `python <entry>` |
| **Streamlit** | `import streamlit` or `streamlit_app.py` | `streamlit run <file> --server.headless true` |
| **Python Script / Standalone** | `app.py`, `main.py`, `server.py`, etc. | `python <file>` inside managed virtual environment |
| **Go** | `go.mod`, entry point in root or `cmd/*` | `go run <entry>` |
| **Rust** | `Cargo.toml` | `cargo run` |
| **Java (Maven / Gradle)** | `pom.xml`, `build.gradle`, or wrapper scripts | `mvn spring-boot:run` / `gradle bootRun` |
| **PHP & Laravel** | `artisan`, `composer.json`, `index.php` | `php artisan serve` or `php -S localhost:8000` |
| **Ruby on Rails / Rack** | `Gemfile`, `config.ru` | `bin/rails server` or `bundle exec rackup` |
| **Static HTML** | `index.html` | Built-in zero-dependency HTTP server with local routing |
| **Docker Compose** | `docker-compose.yml` or `compose.yaml` | `docker compose up` |

## How It Works

### 1. Smart Delta Installations
- **Python**: Reuses any healthy `.venv`, `venv`, or `env` directory. If dependencies are already satisfied, installation is skipped entirely. When creating a virtual environment, it enables `--system-site-packages` so heavy pre-installed packages (such as NumPy, PyTorch, or Pandas) do not need to be re-downloaded. Supports `requirements.txt` (including includes and nested files), `pyproject.toml` (PEP 621 & Poetry), `Pipfile`, and `setup.py`.
- **Node.js**: Automatically identifies the project's preferred package manager (`pnpm`, `yarn`, `bun`, or `npm`) based on lockfiles or `packageManager` declarations. Uses `npm ci` when clean lockfiles exist, falling back to `npm install --no-save` to ensure your repository files are never unintentionally modified.
- **Environment Files**: Automatically creates `.env` from `.env.example` if no `.env` exists.

### 2. Multi-Service Monorepo Support
If a project contains separated frontend and backend services (such as `frontend/` and `backend/`, `client/` and `server/`, or `apps/*`), `runit` runs them concurrently in a single terminal with organized, color-coded logging. If one service depends on another that is still booting up, connection failures receive an automatic grace-period retry.

### 3. Leak-Free Process Lifecycle
Stopping complex applications with child processes often leaves orphaned processes behind. `runit` addresses this across operating systems:
- On POSIX systems (Linux & macOS), processes are tracked via isolated process groups and OS tags, ensuring even detached daemons (`setsid`) terminate cleanly upon `Ctrl+C`.
- On Windows, a background guardian monitor tracks process trees and cleans up child processes if the parent exits or is terminated.
- Run `runit status` anytime to view active sessions, or `runit stop` to clean up a running project.

## Security

`runit` executes actual code and install scripts from the projects you target. **Only use it on projects from authors or sources you trust.**

Built-in security safeguards:
- **First-run Approval**: Interactive confirmation prompts show the exact commands, scripts, and install hooks before execution.
- **Secret Isolation**: Cloud provider credentials (AWS, GCP, Azure, GitHub tokens, Kubernetes configs, and private keys) are stripped from the environment during dependency installation steps.
- **Registry Guard**: Alerts you if a project attempts to pull packages from private or custom package registries via `.npmrc`, `.yarnrc`, or custom pip URLs.
- **Local Static Server**: Built-in static file server enforces hostname restrictions, refuses directory traversal attempts, and hides sensitive dotfiles (`.git`, `.env`).
- **Root/Admin Warning**: Warns immediately if run with elevated administrative privileges.

For detailed security guidelines, refer to [SECURITY.md](SECURITY.md).

## Troubleshooting & Diagnostics

`runit` includes built-in diagnostics for frequent setup issues:
- **Port Conflict (`EADDRINUSE`)**: Identifies which process holds the port and suggests alternative port overrides.
- **Missing Compilers**: Identifies when native binary builds fail and suggests the exact OS package manager command needed (e.g. `winget`, `brew`, or `apt` commands for Visual Studio Build Tools, `gcc`, or `make`).
- **Missing Module / Package**: Identifies unlisted imports and suggests the precise command to add them.
- **Pending Migrations**: Detects unapplied Django migrations and suggests running `manage.py migrate`.
